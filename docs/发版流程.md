# DocMind 发版流程（成熟版）

> 目标：**每个到达用户手里的安装包，都已在干净环境验证过「开箱即用」。**
> 闸门原则：R3 冒烟验收不通过，绝不发布——历史事故（用户机后端全灭）的根源就是跳过这一步。

---

## R0 环境准备（打包机，一次性）

| 依赖 | 用途 | 备注 |
|---|---|---|
| .NET 8 SDK | WPF 单文件发布 | |
| Python 3.11（加入 PATH） | 构建便携运行时 | 仅打包机需要，用户机不需要 |
| Inno Setup 6 | 编译安装包 | 默认装 `%LOCALAPPDATA%\Programs\Inno Setup 6` 即可被脚本发现 |
| 网络 | 下载 embeddable Python / 依赖 | 全程国内镜像，无需代理 |

干净测试机准备（R3 用，可虚拟机）：**不装 Python**、Windows 10 1809+ / 11 x64、新建一个用户名不同的本地账户。

---

## R1 版本定版与质量门槛

1. **版本号唯一来源**：改 `scripts/publish_release.bat` 里的 `APP_VERSION`（安装包名、ZIP 名、提示文案全部跟随，禁止其他地方手改）。
2. 同步更新 `docs/` 中受影响的使用说明 / 部署指南；有新依赖时同步 `requirements-*.txt`（锁定版本，不跑自由解析）。
3. **质量门槛（全绿才准进 R2）**：
   - `pytest tests/` 全绿（C 盘剩余 ≥10GB，避免低磁盘造成环境性误报）；
   - `dotnet test DocMind.Tests` 全绿；
   - 手工过一遍主流程（导入→检索→对话）确认无回归。

---

## R2 一键构建

```bat
scripts\publish_release.bat
```

脚本自动完成（全程国内镜像）：

1. `dotnet publish` WPF 单文件（self-contained）；
2. **便携 Python 运行时**构建（`python-runtime\` 已存在则跳过——⚠️ 依赖有变或 Python 版本升级时**必须删除该目录强制重建**）；
3. 绿色便携版 ZIP（内含 `python\`、`start.bat`）→ `installer\Output\DocMind-vX.Y.Z-win-x64.zip`；
4. Inno Setup 编译安装包 → `installer\Output\DocMind-Setup-X.Y.Z.exe`。

产物自检（构建机上一分钟）：
- `python-runtime\python.exe -m doc2mind serve --port 8801` 能启动；
- ZIP 解压后目录含 `python\`、`start.bat`，**不含** `.venv`；
- 安装包体积合理（含运行时约 300-500MB 量级）。

## R3 冒烟验收（发布闸门，不可跳过）

三机矩阵，每机按同一张检查单走：

| 机器 | 覆盖场景 | 用哪个产物 |
|---|---|---|
| 开发机 | 回归：老功能不破 | 安装包 |
| 干净机 A（无 Python、不同用户名） | **普通用户首启的真实还原** | 安装包 |
| 干净机 B（虚拟机即可） | 绿色版 + 离线 + U 盘场景 | ZIP |

**检查单（每机 ≤10 分钟，逐项勾）**：

- [ ] 双击安装：全程**无管理员弹窗**，装到 `%LOCALAPPDATA%\Programs\DocMind`
- [ ] 首次启动：后端状态灯 ≤30s 变绿（若弹「后端启动失败」，看弹窗内【环境诊断】——出现「虚拟环境绑定的基础 Python 不存在」= 便携运行时没打进去，回 R2）
- [ ] 首次模型下载走镜像成功（或离线机已拷 `fastembed_cache`）
- [ ] 导入一个 md + 一个文字版 PDF → 检索命中
- [ ] 设置页「环境自检」无红色项；「外部组件路径」Poppler 行显示 ❌ + 可点「自动寻找」不崩
- [ ] （可选进阶）装 OCR 组件全程：不弹「后端启动失败」误报 → 「安装完成，后端已重启」→ 诊断面板 paddle 变绿 → 导入扫描 PDF 出文字
- [ ] 卸载：弹出「是否删除用户数据」询问，默认保留

**任何一项不过 → 停止发布，回到开发修复，重走 R1-R3。**

---

## R4 发布

1. GitHub Release 上传两个产物（Setup exe + 便携 ZIP）+ Release Notes：
   - 本版新功能 / 修复（面向用户的语言，不写内部术语）；
   - **升级注意**：直接覆盖安装即可，用户数据（知识库/设置/聊天记录）在 `%LOCALAPPDATA%` 与 `%APPDATA%`，不受影响；
   - 已知问题与规避方法。
2. 版本回退预案：发坏包 → 删除 Release 附件 + 置顶说明；AppId 固定不变，修复版可直接覆盖安装。
3. 打 git tag（`vX.Y.Z`）与 Release 页关联。

---

## R5 发布后

1. 用户反馈统一走 GitHub Issues，先打 `needs-triage`；
2. 值得沉淀的经验（报错根因+解法、第三方库坑）`ingest_text` 入知识库（collection=docmind），供后续发版与排障检索；
3. 每次发版后回看 R3 检查单是否有新增项（新功能 = 新冒烟项），保持清单与环境同步演进。
