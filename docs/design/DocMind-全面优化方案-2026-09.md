# DocMind 全面优化方案

> 版本：v1.0  
> 日期：2026-09-24  
> 适用范围：WPF 客户端、Python 后端、知识库、RAG/Agent 对话、发布交付

## 1. 方案结论

DocMind 不应继续沿着“再增加一个 AI 功能”的方向扩张，而应收敛为：

> **本地优先、证据可追溯的知识研究工作台。**

下一阶段的核心目标不是功能数量，而是让用户稳定完成以下闭环：

```text
导入资料 → 确认资料已可检索 → 基于资料提问 → 查看证据 → 继续追问/导出结果
```

优化优先级：

1. 先修复回答可信度、布局遮挡和状态反馈问题。
2. 再降低首次使用和配置门槛。
3. 然后统一 UI 设计系统和知识库管理体验。
4. 最后补齐导出、发布、诊断和长期维护能力。

## 2. 产品目标与非目标

### 2.1 产品目标

- 让普通用户不理解 BM25、chunk、embedding、SSE 等术语，也能完成首次问答。
- 让用户能判断回答是否来自自己的资料，而不是只能“凭感觉相信”。
- 让导入、索引、检索、回答、引用、导出形成可回溯链路。
- 保持本地优先：资料位置、隐私边界、模型调用范围清晰可见。
- 让 UI 具备专业桌面工具的秩序感，而不是功能堆叠感。

### 2.2 非目标

- 暂不追求做成通用聊天社交产品。
- 暂不同时支持大量新模型、新格式和新 Agent 工具。
- 暂不为了“看起来智能”增加不可解释的自动操作。

## 3. 当前主要问题

### P0：可信度与主流程问题

- HTML/WebView 预览可能覆盖消息流和输入区。
- 用户消息、空气泡、流式中间态存在重复或残留风险。
- 正文中的引用数量与来源列表可能不一致。
- 检索降级、单来源、无本地证据时，用户不能一眼理解当前回答的可靠程度。
- 取消、超时、后端离线、LLM 未配置的恢复路径不够统一。

### P1：首次使用和复杂度问题

- 用户首次打开后，不一定知道先配置什么、先导入什么。
- 设置页技术字段过多，普通用户无法判断哪些是必填项。
- 自动、知识库、Agent、联网等模式的差异和成本不够清楚。
- 思考过程、工具步骤、来源列表同时展开时，信息密度过高。

### P1：视觉与交互问题

- 主题色、阴影、圆角和控件高度曾存在散值。
- 键盘焦点、Tab 导航、禁用态和错误态需要统一。
- ChatView 文件过大，聊天气泡、输入区、来源、预览和弹窗维护成本高。

### P2：长期使用与交付问题

- 会话标题、历史整理和重复会话处理仍可加强。
- 文档导入后的质量反馈、集合治理、回收站和重建索引需要形成完整闭环。
- 打包、备份、迁移、诊断和日志对普通用户仍偏技术化。

## 4. 目标体验

### 4.1 首次使用

1. 启动后显示三步引导：配置模型、导入资料、开始提问。
2. 未配置 LLM 时，在聊天页直接显示配置入口，不等用户发送后才报错。
3. 导入任务显示阶段、进度、预计剩余工作和可执行的失败操作。
4. 导入完成后明确显示“已可检索”，并提供一个示例问题。

### 4.2 一次问答

1. 发送后立即进入真实流式状态。
2. 状态栏只显示关键阶段：准备资料、检索中、生成中、已完成或已降级。
3. 思考过程默认折叠，工具明细按需展开。
4. 回答底部显示证据摘要：本地来源、网页来源、降级状态、证据强度。
5. 每条引用可以打开原文并定位到对应片段。
6. HTML、Markdown、纯文本回答使用独立且稳定的阅读区域，不覆盖输入区。

### 4.3 长期使用

- 会话自动生成可读标题，支持重命名、置顶、归档和删除恢复。
- 集合有质量概览：文档数、最近更新时间、缺少摘要数、重复风险、索引状态。
- 回答可以继续追问、保存为笔记、导出为 DOCX/PPTX/Markdown。
- 所有关键失败都有“重试、查看详情、打开设置、重新索引”等动作。

## 5. 分阶段实施计划

### Phase 0：基线与设计系统收口（1-2 天）

**交付物**

- 固定一组演示资料、问题和期望证据，形成黄金用例。
- 整理 `Theme.xaml` / `Theme.Dark.xaml` 的颜色、圆角、间距、控件高度、阴影和动效 token。
- 建立 light/dark 两套截图基线和最小回归清单。
- 为每一批改动定义统一验收命令：后端测试、WPF 测试、smoke、手工主流程。

**验收**

- 所有新 UI 颜色来自资源 token，不在 View 中新增硬编码颜色。
- 主要按钮、输入框、ComboBox、CheckBox、ListBoxItem 均有 hover、pressed、disabled、keyboard focus 状态。
- 主题切换后没有残留旧色。

### Phase 1：回答可信度与聊天主流程（3-5 天）

**交付物**

- 统一聊天事件模型：`status`、`tool_started`、`evidence_ready`、`token`、`done`、`error`、`degraded`。
- 修复 HTML/WebView 与消息列表、输入区的布局隔离问题。
- 统一用户消息、助手消息、流式中间态的渲染条件，禁止空泡和重复泡。
- 证据摘要直接使用后端结构化字段，不由前端根据 Sources 猜测。
- 单来源、无本地命中、网页未抓取、检索降级时显示明确提示。
- 思考过程默认折叠，工具步骤只展示阶段结论，详情按需展开。

**验收指标**

- 20 条黄金问题中，正文引用数量与来源列表 100% 一致。
- HTML 预览在任何窗口尺寸下不覆盖输入区。
- 首个 token 到达后立即渲染，不等待完整回答。
- 点击停止后 2 秒内停止前端渲染和后端任务。
- 断网、无 Key、超时三类错误均有可执行恢复动作。

### Phase 2：首次使用与设置体验（3-5 天）

**交付物**

- 聊天页未配置模型时显示三步引导卡。
- 设置页拆成“快速开始、知识库、模型与连接、高级设置”四层。
- 顶部增加当前生效配置卡：嵌入模型、LLM 服务商、模型、Key 状态、后端状态。
- 每个字段标识“保存即生效”或“重启后生效”。
- Key 使用“已配置/未配置”状态徽章，清除操作必须二次确认。
- 后端离线统一使用全局横幅：重新检测、一键重启、查看日志。

**验收指标**

- 新用户从启动到第一次成功问答不需要阅读日志或终端。
- 设置首屏只出现用户必须理解的字段，高级技术字段默认收起。
- 所有配置失败都能在页面内定位到下一步动作。

### Phase 3：知识库生命周期（3-5 天）

**交付物**

- 导入流程拆为：选择文件、确认集合、解析预览、执行索引、完成摘要。
- 导入任务进入统一任务中心，支持查看进度、取消、重试和查看失败原因。
- 集合页增加质量卡：文档数、索引状态、最近更新、缺摘要、重复候选。
- 删除统一进入回收站；恢复后明确提示需要重新摄入或重建索引。
- `curate` 提供预览与落盘两步，去重和合并永不静默执行。
- 搜索结果显示命中原因、相似度、来源文档和定位信息。

**验收指标**

- 导入失败可以不丢任务上下文，重新打开应用后仍可查看结果。
- 任何会删除原文的整理动作都有预览和确认。
- 用户能在 10 秒内判断某个集合是否值得用于当前问答。

### Phase 4：UI 统一与代码拆分（2-4 天）

**交付物**

- 为所有页面统一 `PageHeader`、`ContentShell`、`Toolbar`、`SectionCard` 和 `EmptyState`。
- 将 `ChatView.xaml` 拆分为消息流、消息模板、输入 dock、来源区、预览区、弹窗等组件。
- 统一页面内容边距、控件高度、圆角和状态色。
- 完善键盘焦点、Tab 顺序、快捷键提示和高对比状态。
- 动效只保留 120/180/240ms 三档，减少大面积缩放和持续阴影动画。

**验收指标**

- 新页面只需组合已有壳层和组件，不再复制整套标题/工具栏样式。
- 主要路径可完全用键盘完成。
- light/dark 主题下文字、边框、禁用态均有足够层次。

### Phase 5：结果沉淀与创作出口（3-5 天）

**交付物**

- 回答支持保存为笔记、加入知识库、继续追问和导出。
- DOCX/PPTX/Markdown 导出保留来源信息和生成时间。
- Artifact 面板显示草稿、预览、导出、重新生成和版本历史。
- PPT 大纲在生成前进行结构体检：页数、密度、引用完整性、版式风险。

**验收指标**

- 从一个回答生成可分享产物不需要复制粘贴。
- 导出文件可追溯到原会话和证据来源。
- 失败时保留草稿，不丢失用户已编辑内容。

### Phase 6：发布、备份与可观测性（3-5 天）

**交付物**

- 提供一键诊断：后端、数据库、向量模型、LLM、GPU、磁盘空间。
- 提供知识库备份、恢复和迁移说明。
- 默认日志对普通用户隐藏技术细节，支持一键打包诊断信息。
- 打包 Python 运行时和嵌入模型，减少“环境能否启动”的不确定性。
- 记录不含原文内容的匿名性能指标：启动耗时、导入耗时、首 token、失败类型。

**验收指标**

- 干净 Windows 环境可以完成安装、启动、导入和问答。
- 后端异常时用户可以自行完成检测和恢复。
- 备份文件可以在另一台机器上恢复并检索。

## 6. 建议的核心架构决策

### 6.1 统一状态机

聊天、导入、后端连接都使用显式状态机，不用多个布尔值拼接隐式状态。

```text
Idle → Preparing → Retrieving → Generating → Completed
                         ├→ Degraded
                         ├→ Cancelled
                         └→ Failed
```

### 6.2 结构化证据优先

后端返回完整证据对象，前端只负责展示，不根据文本或来源列表重新推断：

- `local_count`
- `web_fetched_count`
- `web_unfetched_count`
- `citation_count`
- `evidence_strength`
- `degraded_retrieval`
- `single_source`
- `fallback_general_knowledge`

### 6.3 页面组件化

优先拆分深模块，而不是把更多逻辑塞进 `ChatView.xaml`：

- `MessageStreamView`
- `MessageBubble`
- `ThinkingSummary`
- `EvidenceBar`
- `ComposerDock`
- `HtmlPreviewPane`
- `SessionDrawer`

每个组件只负责一个清晰的视觉和交互边界。

## 7. 测试与验收矩阵

每个阶段都必须同时通过以下四层：

| 层级 | 内容 | 通过标准 |
|---|---|---|
| 单元测试 | ViewModel、RAG、状态转换、证据计算 | 无新增失败 |
| 契约测试 | SSE 事件顺序、Config、Evidence 结构 | 字段和顺序稳定 |
| Smoke | 导入、搜索、问答、停止、断线恢复 | 0 个 FAIL |
| 视觉验收 | Light/Dark、960x620、1100x720、宽屏 | 无遮挡、无裁切、无残留状态 |

黄金用例至少覆盖：空知识库、单来源、多个来源、无本地命中、网页来源、LLM 未配置、后端离线、长回答、HTML 回答、取消生成。

## 8. 关键指标

### 产品指标

- 首次启动到第一次成功问答完成率 ≥ 80%。
- 导入任务成功率 ≥ 95%。
- 用户打开来源的回答占比持续提升。
- 低证据强度回答被明确标记，不再默认为普通成功。

### 性能指标

- 本地模型首 token 目标 ≤ 3 秒，云端首 token 目标 ≤ 8 秒。
- 停止操作后 ≤ 2 秒停止 UI 增量渲染。
- 1000 条会话历史打开不卡顿。
- 10 万 chunk 集合列表和搜索不阻塞 UI 线程。

### 质量指标

- 黄金问题引用准确率 ≥ 90%。
- 引用数量和来源数量一致率 100%。
- 每次发布前 Python、WPF、smoke、视觉回归全部有记录。

## 9. 立即执行清单

建议下一轮按以下顺序开工：

1. 固定黄金问题、资料和截图基线。
2. 修复 HTML 预览布局隔离。
3. 统一证据对象和引用数量。
4. 修复用户消息重复/空泡/流式残留。
5. 加入无 Key 的聊天页引导。
6. 设置页增加当前生效配置卡。
7. 导入任务接入统一任务状态和失败恢复。
8. 完成 PageHeader、ContentShell 和 Focus 样式收口。
9. 拆分 ChatView 的视觉组件。
10. 最后再做导出、打包和跨机器恢复。

## 10. 风险与边界

- 不要在证据模型稳定前继续扩展新的 Agent 工具，否则会放大 UI 和协议复杂度。
- 不要把 `dedup`、`consolidate` 等破坏性整理做成静默自动操作。
- 不要让前端通过文本猜测后端状态；所有关键状态都应结构化传输。
- 不要为了视觉效果给大面积内容区增加持续阴影或复杂动画。
- 所有配置、导入、删除和导出操作都要保留可恢复路径。
