## 需求 A：插件（GPU/OCR）自适应配置体系商用化

### A0 背景与原始诉求

用户在 GUI 内一键安装 OCR 插件失败：`pip install paddlepaddle...` 报 `WinError 5 拒绝访问`（pip 隐式卸载 numpy 时，numpy DLL 被运行中的后端进程映射锁定）。错误文案「常见原因：网络不可达、包冲突或 wheel 不兼容」与真实原因不符。

**原始要求**：对插件自适应配置功能制定多维度评估标准，评估审议，要求最终功能全部可正常商业使用、稳定可靠、功能可达。

### A1 评估标准（8 维度，商用门槛 ≥85 分且无 P0）

| 维度 | 权重 |
|---|---|
| 功能可达性（安装→检测→重启→生效全闭环） | 20 |
| 稳定可靠性（超时/取消/幂等/并发互斥/失败恢复） | 20 |
| 错误处理与可诊断性（文案与真实原因一致、可指导行动） | 15 |
| 环境适应性（镜像回退、代理、离线 wheel、路径决策） | 12 |
| 一致性（DTO/文案/文档与实现一致，版本锁定统一） | 8 |
| 用户体验（进度反馈、按钮语义、失败引导） | 10 |
| 可测试性（安装执行链路有测试） | 8 |
| 发布一致性（GUI/安装器/pyproject 三条安装路径行为一致） | 7 |

### A2 功能性需求（全部已实现）

| # | 需求 | 实现 |
|---|---|---|
| A-1 | **安装必须在独立进程执行**：后端进程已加载 numpy/paddle/onnxruntime DLL，进程内 pip 必然 WinError 5 | C# 流程改为「停后端 → `python -m doc2mind.install_cli`（独立进程，不加载重依赖）→ 自动重启 → 重新诊断」；后端 SSE 端点加占用预检，命中直接拒绝并指引 |
| A-2 | **错误分类与行动指引**：失败文案必须指向真实原因 | 关键字分类：文件占用（WinError 5 等→指引设置页安装）/ 磁盘不足 / 网络类（→切镜像重试）/ 通用 |
| A-3 | **版本锁定口径统一**：GUI 路径不得自由解析 | `pillow==12.2.0` 对齐 pyproject / requirements-ocr.txt / 安装器三处 |
| A-4 | **镜像回退**：单镜像不可用不得直接失败 | 清华→阿里云→PyPI 顺序回退整序列重试；用户配置 `PIP_INDEX_URL` 时不覆盖 |
| A-5 | **超时与取消**：pip 挂死不得永久卡 UI | 空闲 300s / 总 3600s 超时并 kill 子进程；C# 取消令牌接通 + UI「取消安装」 |
| A-6 | **幂等与并发互斥**：重复安装不得复发文件锁问题 | OCR 已装（importlib.metadata 检测）跳过，`--force`/`force` 字段强制重装；安装端点 asyncio 锁互斥 |
| A-7 | **路径语义不串味** | `install-gpu` 拒绝 cpu/ocr 路径；`install-ocr` 拒绝 GPU 嵌入路径 |
| A-8 | **诊断与文案一致** | `get_gpu_diagnosis` 从不推荐 OCR 路径 → DTO 注释 / `RecommendedPathHint` 对齐现实 |
| A-9 | **半装态可感知** | `install_cli` 写 `plugin_install.json` 状态标记；doctor 体检输出「上次安装未正常收尾」警告与修复指引 |
| A-10 | 质量项 | wheel 平台兼容判定修复（Windows 恒跳过平台检查）、死代码清理、按钮文案按方案区分、导入页 OCR 失败加设置页引导、OCR 语言可配（`DOC2MIND_OCR_LANG` / AppSettings.OcrLanguage） |

### A3 验收口径

- 无 P0 问题；`pytest tests/`（相关子集）与 `dotnet test` 全绿；
- 手动验收：正常安装→诊断→重启→导入扫描件成功；断网走镜像回退；安装中可取消；重复点击幂等；模拟 DLL 占用时文案准确。

## 需求 B：外部组件路径可指定 + 自动寻找可用配置

### B0 原始诉求

1. 用户可以选择配置文件/外部组件的放置位置；
2. 软件自带自动查找并使用可用配置的能力；
3. 默认位置没有配置文件时，点击「自动寻找可用配置」即可完成全文件搜索，找到并自动完成配置；
4. （追问）压缩搜索时间；
5. （补充）U 盘也要纳入扫描。

### B1 适用资源（4 类，config.toml 以环境变量重定向支持）

| 资源 | 锚点 | 校验 | 配置落点 |
|---|---|---|---|
| Poppler（扫描 PDF 渲染） | `pdftoppm.exe` | 目录含锚点文件 | `PopplerPath` → `DOC2MIND_POPPLER_PATH` |
| 后端 Python 解释器 | `python.exe` | 锚点 + `--version` 试运行 | `BackendCommand` |
| 离线安装包 wheels | `*.whl` | 目录含 ≥1 个 whl | `WheelsDir` → `DOCMIND_WHEELS_DIR` |
| 嵌入模型缓存 | `fastembed_cache` 目录 | 目录名匹配 | `EmbedCacheDir` → `DOC2MIND_EMBED_CACHE_DIR` |

### B2 功能性需求（全部已实现）

| # | 需求 | 实现 |
|---|---|---|
| B-1 | **手动指定位置**：用户浏览选择，校验不过不写入 | 「📁 浏览选择…」+ `Validate()` 前置校验 + Toast 反馈 |
| B-2 | **三级递进自动寻找**：显式配置 → 高概率区快扫（秒级）→ 全盘深扫 | `Locate()` / `DeepScanAsync()`；快扫未命中弹确认后才深扫 |
| B-3 | **深扫约束**：**含 U 盘**（DriveType Fixed+Removable）、排除网络盘/光驱/未就绪；跳过 Windows/ProgramData/回收站等黑名单目录；深度 ≤6；跳过重解析点；命中 3 个校验通过候选即提前退出；进度可见、可随时取消 | `ScanRootsAsync` 统一剪枝遍历 |
| B-4 | **搜索时间压缩** | 高概率区优先 + 剪枝 + early-exit + 结果缓存（`resource_scan_cache.json`，二次点击毫秒级）+ 空结果 7 天冷却期；USN Journal 直读列为后续可选增强（本期不做） |
| B-5 | **新环境不锁定开发路径** | 代码零绝对路径（`.venv`/`tools\poppler` 从应用目录向上 ≤6 层相对探测）；已配置路径每次先校验，失效自动回退快扫并在状态栏明示「已配置的路径在本机失效」 |
| B-6 | **配置生效链** | 命中写 `appsettings.json` → 后端启动注入环境变量 → 提示重启后端生效 |
| B-7 | **按键业务逻辑互斥** | 任一扫描进行中：全部「自动寻找/浏览/重新检测」置灰，仅「停止搜索」可点；`IsBusy` 变化显式 `NotifyCanExecuteChanged()`（CommunityToolkit 不走 CommandManager）；多候选自动应用第一个、其余全部列出供「浏览选择」改选 |
| B-8 | **多命中透明** | 深扫多候选不静默：状态栏列出全部候选与改选方式 |

### B3 后端消费链（配套修复）

- `pdf_loader._find_poppler()`：`settings.poppler_path` 提为最高优先级（**原缺陷：配置只影响状态显示，真实渲染从不消费**），失效记告警回退自动探测；
- `config.py`：新增 `poppler_path` 字段（`DOC2MIND_POPPLER_PATH` 自动映射）、`DOC2MIND_CONFIG` 支持 config.toml 位置重定向；
- `doctor` 体检：Poppler 就绪项带来源标注（手动指定 / PATH 自动探测），未就绪给出设置页修复指引。

### B4 明确不做（范围控制）

- 不改 `config.toml` 固定查找链（只加重定向环境变量）；
- 深扫不做多盘并行（顺序扫盘符）；
- Paddle 模型不做自动搬运（只支持指定新位置）；
- USN Journal / Everything 索引加速列为后续可选增强。

### B5 验收口径

- 默认位置无配置 → 快扫命中 / 深扫（含 U 盘）命中并自动配置 / 取消深扫不影响现有功能；
- 配置失效（含跨机拷贝旧配置）→ 明确提示 + 自动兜底，不卡死；
- 搜索期间按钮互斥符合 B-7 契约。
