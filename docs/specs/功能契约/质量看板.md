### 功能：质量看板

**能完成的任务**（一句话，用户视角）：
查看知识库的重复率、元数据缺失、格式分布等质量指标与文档统计，并对知识库执行「AI 整理」（打标签/摘要、归类、去重、归纳合并）以提升检索质量——先只读预览、确认后再执行。

**不能完成的事**（边界，防范围蔓延）：
- 不做原始数据编辑；只读展示 + 整理动作。
- 质量报告字段以后端实际返回为准（⚠️ 规范曾期望的 6 个质量字段后端不存在，见 `core-chain-and-smoke.md` D-08，此处以现有 5 字段 `QualityResponse` 为准）。
- 「AI 整理」不包含实体抽取（`CurateActions` 明确排除 `extract`，`QualityViewModel.cs:231`，图谱抽取走图谱页）。

**前置条件**：后端在线 → 不满足时 `RefreshAsync` 走 `BackendConnectionException` 分支（`QualityViewModel.cs:209-214`），页内 `StatusMessage` 显示「后端不可达：…」；加载失败不缓存，下次进入自动重试（`EnsureLoadedAsync`，`QualityViewModel.cs:44-56`）。
- ⚠️ **缺口（未编号，类比 FC-06）**：「AI 整理」需 LLM，但**未配置 LLM 时后端报错、工作流前置未做事前检查/禁用**（`QualityViewModel.cs:293-316` 直接提交后端，无 `IsLlmConfigured` 事前拦截）。未分配 FC 编号——若纳入整改，参照 FC-06 同类前置条件破口处理。

**输入契约**：可选集合 `Collection`（默认 default/全部）；整理动作固定为 `enrich/categorize/dedup/consolidate`（`QualityViewModel.cs:231`），前端不可改；`dryRun` 由「预览 / 执行」两个入口分别固定（`PreviewCurateAsync`/`ExecuteCurateAsync`，`QualityViewModel.cs:283-288`）。「执行」前置要求先完成一次只读预览（`CanRunCurateExecute`，`QualityViewModel.cs:280`，防有损操作误触发）。

**状态机**：
- 报告加载：`idle → loading → loaded | failed`（`RefreshAsync`，`QualityViewModel.cs:153-226`）。
- AI 整理：`idle → previewing/running → succeeded | cancelled | failed`（`IsCurating` 控制，`QualityViewModel.cs:234-246`；`_curateCts` 提供轮询取消）。

**4 个出口**
- ✅ 成功：报告页展示 `Report`（重复率/元数据缺失/警告 `Warnings`）+ `Stats`（文档数/chunk 数/集合分布）+ 图表（`UpdateChartSeries`，`QualityViewModel.cs:114-147`）；整理预览成功 → 「✅ 预览完成（只读，未写入任何数据）——确认无误后可「执行」」并可点「执行」（`QualityViewModel.cs:365-367`）；整理执行成功 → 摘要 `CurateSummary`（各动作计数，`BuildCurateSummary`，`QualityViewModel.cs:399-424`）。完成判据：报告/统计字段非空且渲染；整理任务 `final.Status != failed/cancelled`。
- ✅ 失败：报告加载按 `ApiException`/`BackendConnectionException`/未知分类给 `StatusMessage`（`QualityViewModel.cs:203-220`）；整理失败 `CurateStatus`「AI 整理X失败: …」（`QualityViewModel.cs:350-354`）或按异常类型报错（`QualityViewModel.cs:375-389`）。「下一步」：修复后端 / 重试预览或执行。
- ✅ 取消：整理轮询可取消（`CancelCuratePolling`，`QualityViewModel.cs:291`，页面离开时中止轮询；任务本身不强制取消，后端 job 继续或自然收敛，`QualityViewModel.cs:290` 注释明确）；`OperationCanceledException` → `CurateStatus`「AI 整理X已取消」（`QualityViewModel.cs:371-374`）。
- ✅ 空态：无警告时 `HasWarnings` 为空（`QualityViewModel.cs:103`）；无集合数据时 `Collections`/图表为空属正常展示（不误导为错误）；后端无报告可整理时摘要给「后端未返回整理报告…」（`QualityViewModel.cs:404-405`）。

**恢复路径**：报告加载失败不缓存（`_hasLoadedOnce` 仅 `_refreshSucceeded` 时置位，`QualityViewModel.cs:44-56`），下次进入自动重试；`InvalidateCache`（`QualityViewModel.cs:56`）供导入完成后强制刷新；整理失败可重新预览/执行。

**可执行测试**：
- `Given 有导入数据 When 刷新质量看板 Then 报告+统计字段渲染 且 与 /v1/stats 文档数一致`
- `Given 后端异常 When 刷新 Then StatusMessage 报错 且下次进入自动重试`
- `Given 未预览 When 点「执行」 Then 按钮禁用 必须先预览`
- `Given 整理失败 When 后端报错 Then CurateStatus 显示失败 且可再预览/执行`
- `Given 页面离开整理中 When 离开 Then 轮询中止 但后端任务不强制取消`
