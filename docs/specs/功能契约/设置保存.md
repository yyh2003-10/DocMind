### 功能：设置保存

**能完成的任务**（一句话，用户视角）：
修改后端连接、嵌入模型、分块、大模型、RAG、重排、主题等配置项并保存，使新配置对后续导入/对话生效，并能确认「保存是否真的生效」。

**不能完成的事**（边界，防范围蔓延）：
- 不作为产品级配置中心（不做账号、权限、插件管理）。
- 不保证「改完立刻全量生效」——不同类别生效语义不同（见状态机与成功出口，FC-04）。
- 不改后端 `config.toml` 的磁盘路径（由后端收到 `POST /v1/config` 后自行落盘；WPF 只写本地 `appsettings.json`）。

**前置条件**：本地可写（`appsettings.json`）；后端**非必需在线**（本地落盘无条件成功，后端推送失败仅告警不阻塞，`SettingsViewModel.cs:1469-1472,1493-1559`）。API Key 解密失败时**保存被阻断**，须先重新输入或清除（`SettingsViewModel.cs:1399-1404`）。
- ⚠️ **缺口 FC-04相关**：后端在线与否不阻断本地保存，但「生效状态」可见性不完整（见成功出口）。

**输入契约**：约 30 个可编辑字段（后端 URL/端口、启动超时、嵌入模型/路径/HF 端点、分块参数、LLM provider/key/baseUrl/model/temperature/maxTokens、RAG topK/system prompt/maxHistoryTokens/mode、重排、GitHub token、主题、文件监控路径等，`SettingsViewModel.cs:458-783,2469-2483`）。类型约束：整型字段（端口、超时、topK 等）必须是合法整数，非法值由 UI 校验/提示。API Key 有特殊语义（见空态出口，FC-05）。`CanSave`（`SettingsViewModel.cs:1282`）= `IsDirty`（有改动才可保存）。

**状态机**：`idle → dirty → (saving → saved) | failed | reverted`
- ⚠️ **缺口 FC-04相关**：无显式 `IsSaving` 状态标志（保存中无 spinner，异步保存期间无双击防护，`SettingsViewModel.cs:1379`）；`reverted` 由 `Revert`（`SettingsViewModel.cs:1640-1696`）和 `ResetToDefaults`（`SettingsViewModel.cs:1698-1762`）进入。

**4 个出口**
- ⚠️ 成功：`StatusMessage` = 「已保存（后端推送失败，重启后端后生效）{keyNote}」或「已保存（模型/分块参数已实时生效；其余变更重启后端生效）{keyNote}」（`SettingsViewModel.cs:1591-1593`）+ 成功通知 + 关键参数变更触发重启横幅 → 后端 URL/命令变更弹重启对话框（`SettingsViewModel.cs:1614-1630`）+ 推送后刷新状态卡（`LoadBackendConfigAsync`，`SettingsViewModel.cs:1605-1608`）。
  - ⚠️ **缺口 FC-04**：生效语义有**三种并存**——① LLM 连接字段「输入即生效」防抖推送运行时（`persist=false`）；② 嵌入/分块/后端类变更**重启后端**生效（重启横幅/对话框）；③ 环境变量 `DOC2MIND_*` 下次启动兜底。状态卡只展示 3 个字段（embed model / LLM provider / LLM model，`SettingsViewModel.cs:615-639`），**没有完整「当前实际生效配置」视图**——用户无法确认 RAG、分块、重排、温度等 25+ 字段是否真的生效。完成判据（部分可观测）：`IsDirty` 复位 + `StatusMessage` 成功文案 + 后端状态卡刷新；「生效」本身无统一可观测判据。
- ✅ 失败：两种层——① 保存前 API Key 解密失败阻断：「保存中止：需要处理 API 密钥」（`SettingsViewModel.cs:1404`），下一步 = 重输 Key 或点「清除」；② 保存异常（外层 catch，`SettingsViewModel.cs:1632-1637`）：`StatusMessage`「保存失败：…」且 `IsDirty` **不复位**，保存按钮仍可用，下一步 = 直接重试。后端推送失败（内层 catch）本地仍成功，给重启横幅引导。
- ✅ 取消：保存中**不可中止**（无取消令牌）。编辑层面的「取消」= `Revert()`（`SettingsViewModel.cs:1640-1696`）恢复到最后一次已保存值；`ResetToDefaults()` 重置为出厂默认（需再点保存）。API Key 清除确认弹窗支持取消（`CancelClearApiKey`，`SettingsViewModel.cs:1789-1794`）。
- ⚠️ 空态：API Key「留空 = 保留原值」有显式状态徽章 `ApiKeyStatusText`（「已配置 ✓ 」/「未配置」，`SettingsViewModel.cs:611,643`，后端 `_backendApiKeyConfigured` 兜底）+「清除」按钮 + 清除确认（FC-05 **✅ 已实现**）。
  - ⚠️ **缺口 FC-05相关**：GitHub Token 同「留空保留」语义 +「清除」按钮，但 `HasSavedGithubToken`（`SettingsViewModel.cs:673`）**只查本地快照**不查后端状态，且无状态徽章文本；BaseUrl/Model 的「曾配置+现清空 → 推空串显式清除」语义亦无「已配置/未配置」徽章。

**恢复路径**：
- 失败保存：`IsDirty` 保留，用户可直接重试；字段仍留在内存，无数据丢失。
- 后端推送失败：本地已保存，引导「立即平滑重启后端」或依赖环境变量下次启动生效（`SettingsViewModel.cs:2527-2557`）。
- 写完发生后端离线的 `config.toml` 失效：重启后端时由 `BackendProcessService` 注入 `DOC2MIND_*` 环境变量兜底（`BackendProcessService.cs:389-437`）。

**可执行测试**：
- `Given 有改动 When 保存 Then 本地 appsettings.json 更新 且 StatusMessage 成功 且 IsDirty 复位`
- `Given API Key 留空且未点清除 When 保存 Then 保留原值 且徽章仍为「已配置 ✓」`（✅ 锁定 FC-05）
- `Given API Key 解密失败且未重输/清除 When 保存 Then 阻断 提示处理密钥`
- `Given 改动嵌入模型 When 保存 Then 触发重启横幅 提示重启后端生效`
- `Given 后端离线 When 保存 Then 本地保存成功 且给「重启后端后生效」提示`
