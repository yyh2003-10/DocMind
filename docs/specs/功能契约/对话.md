### 功能：对话

**能完成的任务**（一句话，用户视角）：
基于知识库（可选附件）向大模型提问，获得带来源引用的流式回答，并可继续多轮、重新生成、撤回。

**不能完成的事**（边界，防范围蔓延）：
- 不保证未导入内容的回答（RAG 从知识库检索，无命中时模型可能仍作答但来源为空）。
- 不解析超出支持格式的附件（pdf/docx/xlsx/pptx/md/图片/代码，`ChatViewModel.cs:653`）。
- 不自动重试（见恢复路径，无自动退避重试机制）。

**前置条件**：LLM 已配置（`IsLlmConfigured`，`ChatViewModel.cs:946-948`，provider 非 none 且 Key 有效）→ 不满足时：
- ✅ **FC-02 已实现**：发送前 `SendCoreAsync` 硬拦截（`ChatViewModel.cs:1373-1379`），不发注定失败的请求；空态引导 `EmptyGuideText`（`ChatViewModel.cs:951-962`）分「已配置/未配置」两模态，未配置时给出到设置页的步骤；`NavigateToSettingsRequested` 事件 + `NavigateToSettings()` 命令（`ChatViewModel.cs:93,96-97`）跳转设置页。
- 后端不可达 → `BackendConnectionException` 页内报错（`ChatViewModel.cs:1791-1802`），见失败出口。

**输入契约**：`InputText` 字符串，或附件（`PendingAttachments`）。`CanSend`（`ChatViewModel.cs:964`）= 非忙碌且（有文本或附件）。空文本+无附件 → 按钮禁用、不发请求；空文本+有附件 → 自动以「请分析并总结我上传的附件内容。」代问（`ChatViewModel.cs:982-985`）。非法输入不产生网络请求。

**状态机**：`idle → streaming(user_msg 已发+assistant 占位) → done(succeeded, with/without partial) | cancelled | failed`
（`IsBusy` 控制：`ChatViewModel.cs:732-748`；`SendCommand`/`StopCommand`/`RegenerateCommand` 可用性级联；`_cts` 提供取消协调。）

**4 个出口**
- ✅ 成功：流式气泡最终渲染完整回答 + 来源引用 `[n]` 角标（`onDone`，`ChatViewModel.cs:1620-1660`）+ 状态区显示「模型: X (provider) · 引用 N 块 · 耗时 X ms」（`ChatViewModel.cs:1682`）+ 末条回答出现「重新生成」按钮。完成判据：`assistantMsg.IsLoading == false` 且 `Sources` 填充且 `Model`/`Provider` 写入；新会话自动出现在会话列表。
- ❌ 失败（FC-03 破口）：分三类捕获，均恢复 `InputText = query`（`ChatViewModel.cs:1739,1789,1801,1813`）：
  - `ApiException` → 按 `LlmConfigHint` 分类（Key 无效/未配置 → 引导到设置页；`ChatViewModel.cs:1761-1790,1834-1851`）；已收 token 保留 + 「⚠️ 回答中断」，未收则整气泡替换为错误。
  - `BackendConnectionException` → 页内报「❌ 无法连接到后端服务…」，**未走全局离线横幅**（`ChatViewModel.cs:1791-1802`，即 FC-03）。
  - 流中断无 onDone → 「回答生成失败 · 连接中断」，部分内容保留 + 提示「可点击重新生成」（`ChatViewModel.cs:1715-1740`）。
  - 「下一步」：改词重发 / 「重新生成」/「撤回」后重发；Key/配置类错误引导到设置页。
- ✅ 取消：`IsBusy` 时出现「停止」（`ShowStop`，`ChatViewModel.cs:973`）→ `Stop()` 调 `_cts.Cancel()`（`ChatViewModel.cs:1854-1866`）→ `OperationCanceledException` 处理（`ChatViewModel.cs:1749-1760`）：状态区「已停止生成」，已流出的部分内容**保留**（空则置「（已停止生成）」），思考区收尾。后端流由取消令牌协同停止。
- ✅ 空态：`ShowEmptyGuide`（`ChatViewModel.cs:937`）= 非忙碌且无消息时显示 `EmptyGuideText` 双模态引导（已配置 → 提示去导入；未配置 → 引导去设置）。

**恢复路径**：
- 失败/取消后 `IsBusy` 复位，`CanSend` 恢复。
- 「重新生成」`RegenerateAsync`（`ChatViewModel.cs:1343`）：删末条失败/不满意的 assistant 消息，同 `chatId` 重发用户问题（保持上下文连贯）。
- 「撤回」`Withdraw`（`ChatViewModel.cs:1925`）：删除 user 消息与其回答，提问回填输入框。
- 系统级：后端恢复在线后 `RefreshModelSeedAsync`/`RefreshSessionsAsync`（`ChatViewModel.cs:2409-2419`）由外层重播配置与会话。

**可执行测试**：
- `Given LLM 未配置 When 发送 Then 不产生网络请求 且触发 NavigateToSettingsRequested`（✅，锁定 FC-02，对应原 FC-02 锁定测试）
- `Given LLM 已配置+合法提问 When 发送 Then 回答流式渲染 且来源[ n ]可见 且状态区含模型/引用/耗时`
- `Given 生成中 When 点停止 Then 状态区「已停止生成」 且已流出内容保留 且可重新生成`
- `Given 后端不可达 When 发送 Then 页内报错 且 query 回填可重发`（⚠️ 未走全局横幅，FC-03）
- `Given 空输入+无附件 When 发送 Then 按钮禁用 不发请求`
- `Given 空输入+有附件 When 发送 Then 自动以总结提示代问`
