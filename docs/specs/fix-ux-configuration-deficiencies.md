# 规格：DocMind UI/配置体验改进（对外发布就绪）

> 状态：`ready-for-agent`
> 生成自：UI/配置体验审查（2026-08-19，Staff Engineer Mode · architecture-decisions）
> 前置约束：**目标用户是对外发布的普通用户**（非技术背景），所有验收标准以此为基准。

## Problem Statement

DocMind 当前 UI 与配置流程按「开发者自用」标准设计，对外发布存在四类系统性缺陷：

1. **配置方法有缺陷**：生效时机三种语义并存（实时生效/重启后端/下条消息生效）且不可预测；「当前实际生效配置」无统一视图（本地 appsettings / 环境变量 / 后端运行时三源不可见）；API Key「留空=保留原值、须点清除按钮才真清除」的隐性语义反直觉；设置页 10 类 30+ 字段纵向堆叠，工程师参数（轮询毫秒/分块 token/HF 端点）全部裸露。
2. **首次上手零引导**：无首用向导；LLM 未配置要到对话页发消息报错后才发现；「集合/分块/嵌入/混合检索」等术语无解释直接暴露。
3. **等待与进度反馈不足**：导入取消是假取消（仅停前端轮询，后端继续跑）；对话为伪流式（全部生成完才显示，用户以为卡死）。
4. **错误提示与恢复路径缺失**：后端不可达时各页零散报错、无「检测→一键重启」统一恢复路径；错误兜底指向后端日志（普通用户不会看也看不懂）。

完整缺陷清单（19 项，含代码证据）：C1-C8（配置）/ F1-F4（首用）/ W1-W4（等待）/ E1-E3（错误），见审查会话记录。本 spec 覆盖其中 C1-C8、F2-F4、W2、E1-E3；F1、W1、W3、W4 登记为第二批缺口。

## Solution

按四批次实施「止血修复 + 设置页信息架构重构 + 配置状态透明化」：

- **批次 1**：设置页重组为「快速开始 / 知识库 / 高级（默认折叠）」三区，嵌入模型场景化，普通用户主路径零技术参数。
- **批次 2**：配置状态透明化——当前生效配置状态卡、分区生效标签、保存后按需弹「立即重启后端」、API Key 显式状态徽章。
- **批次 3**：对话 SSE 真流式（HANDOVER P1 既定方案）+ LLM 未配置事前引导卡。
- **批次 4**：全局后端离线恢复横幅、「集合→分组」术语统一、文档对齐。

## User Stories

### 批次 1 — 设置页信息架构重构（C4/C5/C6）

1. 作为普通用户，我打开设置页第一眼看到的是「快速开始」区（LLM 服务商预设 / API Key / 模型名 / 测试连接），不展开任何折叠就能完成对话功能配置
2. 作为普通用户，「知识库」区里我按场景选嵌入模型（「中文文档推荐」「英文文档」「多语言」「更高精度」），而不是面对 `BAAI/bge-small-zh-v1.5` 这类裸英文串
3. 作为普通用户，轮询间隔(ms)、启动超时(s)、分块 token/字符×4、HF 镜像端点、RAG 历史预算这些工程师参数默认收进「高级」折叠区，我看不到也不会误改
4. 作为高级用户，展开「高级」区后原 30+ 字段全部仍可配置（只重排不删减）

### 批次 2 — 配置状态透明化（C1/C2/C3/C7/E3）

5. 作为普通用户，设置页顶部有「当前生效配置」状态卡，显示后端**实际在用**的嵌入模型、LLM 提供商与模型、Key 配置状态（数据来自 GET /v1/config），与「本次未保存的修改」并列可对比
6. 作为普通用户，每个分区有明确生效标签：「保存即生效」或「重启后端后生效」，我不用猜
7. 作为普通用户，我保存的改动里含重启类字段时，保存成功后立即弹「立即重启后端 / 稍后」确认，点一下就完成生效，不需要自己去页面深处找重启按钮
8. 作为普通用户，API Key 旁边有显式状态徽章（未配置 / 已配置 ✓），「清除」走确认对话框——留空保存不再是唯一且隐性的「保留原值」通道
9. 作为普通用户，后端推送失败时我看到的是一句人话 + 一个动作按钮（如「已保存到本地，点击重启后端生效」），而不是三行技术解释

### 批次 3 — 对话真流式 + 事前引导（W2/F2）

10. 作为普通用户，对话回答逐字出现（真流式），首个 token 到达即开始渲染，我不会误以为软件卡死
11. 作为普通用户，LLM 未配置时我进入对话页就看到引导卡（三步说明 + 「前往配置大模型」按钮），而不是发完消息才收到报错

### 批次 4 — 离线恢复 + 术语与文档对齐（E1/C8/F3/F4 部分）

12. 作为普通用户，后端掉线时全局出现离线横幅：「重新检测 / 一键重启后端 / 查看日志」三个按钮，点重启后横幅消失，全程不需要读日志
13. 作为普通用户，全软件统一叫「分组」（原「集合」），tooltip 保留英文对照；文档同步更新
14. 作为用户，使用说明与实际行为一致（「保存即推送」语义），不再误导我重启客户端

## Implementation Decisions

### 批次 1 模块修改范围

- **前端** `DocMind/Views/SettingsView.xaml`：现有区段（后端连接/性能/模型与分块/GPU/大模型对话/启动选项/文件监控/外观/关于体检）重组为三区：
  - **快速开始**：现「大模型对话」区的预设/Key/模型/测试连接部分上移至页首
  - **知识库**：嵌入模型（场景化）+ 分块参数折叠为「调优」子区
  - **高级（默认折叠）**：后端连接、性能、启动选项、文件监控、RAG 参数（TopK/温度/历史预算/系统提示词）、外观
- **前端** `DocMind/ViewModels/SettingsViewModel.cs`：新增分区可见性属性；`SupportedEmbedModels` 改为场景化包装（场景名 + 模型 ID 副标题，原 ID 仍为实际值）
- 绑定路径与属性名不变（只挪容器），保护现有 47 项 WPF 测试

### 批次 2 模块修改范围

- **前端** `SettingsViewModel.cs`：
  - 扩展 `LoadBackendConfigAsync()`：除 Key 状态外回填 EmbedModel / LlmProvider / LlmModel 到状态卡属性
  - 保存流程新增「重启类字段变更检测」（后端连接/启动超时/后端命令等不参与 /v1/config 推送的字段）→ 触发重启确认
  - Key 徽章属性 + 清除确认流（替代 `_clearApiKeyRequested` 的纯隐性语义，保留其内部逻辑兼容）
- **前端** `SettingsView.xaml`：状态卡 + 分区生效标签 + 徽章 UI
- **后端**：无改动（`BackendConfig` 已含 `EmbedModel`/`LlmProvider`/`LlmModel`/`LlmApiKeyConfigured` 全部所需字段）

### 批次 3 模块修改范围

- **后端** `src/doc2mind/server/http.py`：`/v1/chat/stream` 从「`run_in_executor` + `list()` 全量收集」改为 **asyncio.Queue 桥接**（工作线程跑 `rag_answer_stream` 逐帧 put，async 生成器逐帧 get + yield），SSE 帧格式（token/done）不变
- **前端** `DocMind/Services/Doc2kbApiService.cs`：新增 SSE 客户端（`HttpClient.SendAsync` + `ResponseHeadersRead` + 逐行解析 `data:` 帧）
- **前端** `DocMind/ViewModels/ChatViewModel.cs` + `ChatView.xaml`：token 帧增量更新气泡、done 帧落 sources；LLM 未配置空态引导卡（复用现有 `NavigateToSettingsRequested` 事件）

### 批次 4 模块修改范围

- **前端** `MainWindow.xaml` + `MainViewModel.cs`：基于现有 `BackendState.Offline` 状态机与 `CanStartBackend`，新增全局离线横幅（重新检测/一键重启/查看日志），替代各页零散「后端不可达」报错
- **前端** 各 View/ViewModel 文案：「集合」→「分组」统一（代码标识符、API 字段、集合名默认值 `default` 均不动，仅 UI 显示文案）
- **文档** `docs/使用说明-每个页面在干嘛.md`：对齐「保存即推送」语义、术语更新

### API 合约变更

无破坏性变更。唯一后端改动是批次 3 的 SSE 实现内部机制（伪流式→真流式），**帧格式与字段完全不变**，现有 pytest 流式测试（`tests/test_rag.py` 4 项）作为契约守护。
