# ISSUE-05 模型延迟诊断与推荐策略

## 背景

用户两分钟无回答；截图显示检索/联网已结束，卡在「正在生成回答」；nemotron 超大模型极慢，换 gpt-oss-20b 约 46s 完成。

## 目标

1. 可区分耗时：检索 / 联网 / **生成首 token** / 总时长。  
2. 超时/慢模型有明确提示与操作建议。  
3. 产品侧给出模型选用建议（日常 vs 重型）。

## 验收标准

- [ ] done/状态中可见分阶段耗时（至少：total 与 生成相关）  
- [ ] 首 token 超过阈值（如 30s）时 status 提示「模型响应较慢…」  
- [ ] 超时错误文案包含：检查模型/关闭联网/去设置换模型  
- [ ] 设置或文档中有「模型速度」说明  
- [ ] 回归：正常快速模型不误报  

## 建议实现点

- `rag.py` / `http.py`：TTFT、阶段 elapsed  
- WPF 状态栏展示  
- 日志字段规范化  

## 产出

- 诊断说明 + 推荐配置表
