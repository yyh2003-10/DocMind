# DocMind 2026 H2 聚焦计划：科研渠道 × 巩固闭环

- **状态：规划完成，未实施**（2026-08-23）。任何代码/ schema 变更在产品负责人明确下达推进指令前不得执行；推进时按里程碑顺序开工，首个任务为 M1.1。
- 制定时间：2026-08-23（修订版：楔子功能由「出题/教案」校正为「科研/写作」）
- 决策依据：`docs/research/市场调研-2026-08-AI知识库赛道全景.md`（赛道调研）+ 产品定位讨论
- 定位一句话：**存在用户电脑里、会主动帮他巩固的知识引擎**
- 渠道策略：高校教师人脉主动推（以**科研者**身份切入，而非教学者；导师 → 研究生自然扩散），开发者走 MCP 被动自传播

## 一个引擎，三张皮肤（用户分层与核心循环的映射）

```
摄入资料 → 组织（检索/图谱/整理）→ 巩固（复习/蒸馏）→ 输出交付物
```

| 用户群 | 核心循环 | 对应能力 | 渠道姿态 |
|---|---|---|---|
| 科研人群（大学老师/研究生） | 文献 PDF → 图谱/检索 → 文献卡片/综述 → 论文写作 | 摄入+蒸馏+creator | **主动推（主楔子）** |
| 开发者 | 文档/代码 → 检索 → 经验沉淀 → MCP 供 agent 调用 | MCP 已有 | 被动自传播 |
| 普通用户 | 知识记录 → 随时查看 → 复习巩固 | 检索+巩固闭环 | 场景包自然承接 |

市场依据：科研/写作方向被 Elicit（$30M+ 融资、200 万研究者）、SciSpace、Heptabase（$120 万 ARR）、NotebookLM 用途数据多重验证，是本赛道验证最强的楔子；出题组卷验证最弱，降级为场景包附加模板。

## 明确不做（边界）

- ❌ 出题组卷/教案生成作为主线功能（保留为科研场景包内的附加模板，零专门开发投入）
- ❌ LMS 对接、成绩管理、IDE 插件、代码托管集成
- ❌ 自建通用 agent harness / 通用代码插件平台（延后到有真实第三方需求）
- ❌ 企业私有化主动销售、学校级采购对接（被动承接）
- ❌ 面向学生的 C 端刷题产品

## 阶段 0：科研用户访谈验证（与阶段 1 并行，1 周内完成）

**目的**：验证科研楔子内部的优先级（文献综述工作台 vs 写作辅助），并积累种子用户。

- 访谈 5–8 位教师 + 若干研究生（理工 / 文科 / 医学至少各 1），每人 30 分钟
- 验证三件事：① 文献管理现状（Zotero/EndNote/知网？痛点在哪）；② 写综述/论文最耗时的环节（找文献？读文献？组织观点？成稿？）；③ 对 AI 工具进科研资料的态度与隐私顾虑
- 产出：访谈纪要归档 `docs/research/`，形成阶段 4 路线选择结论
- 不阻塞阶段 1（场景包框架与访谈结果无关）

## 阶段 1：场景包 + 对话式引导配置（2–3 周）

目标：新用户「说一句话 → 场景装好 → 5 分钟可用」。

### M1.1 场景包格式与加载器（数据级插件，非代码插件）

- 新增 `src/doc2mind/core/scenario/`：manifest（id/name/version/target_role）+ `prompts/`（persona 覆盖，复用 `creator/prompts.py` 机制）+ `templates/`（交付物模板）+ `presets/`（集合预设、默认设置）
- 后端 API：`/v1/scenarios` 系列（列出/读取/安装/卸载），manifest 校验 + 失败回滚
- 验收：内置场景包可安装/卸载/列出，重启后状态保持

### M1.2 科研场景包 v1

- **文献卡片蒸馏模板**：复用现有 distill 引擎（`/v1/graph/entities/distill` 本质就是结构化读书卡片生成器），面向文献调优模板（研究问题/方法/结论/可引用点 + 原文出处）
- **综述草稿生成**：利用图谱 topic 层做综述大纲（主题 → 实体 → 关系 → 带引用的段落草稿），导出 DOCX（复用 `creator/exporters`）
- **写作 persona + 文献集合预设**（「文献库」「读书笔记」集合）
- 附加模板：出题/教案（模板文件随包分发，不投入专门开发）
- 验收：对一个有图谱的文献集合，一键生成含主题大纲与原文引用的综述草稿

### M1.3 对话式引导配置（固定引导流 + LLM 意图解析，非 agent 循环）

- 后端 `POST /v1/onboarding/interpret`：解析一句话（科研/开发/普通用户 + 模型偏好），联动 `doctor.py` 体检，生成配置清单
- 用户确认后原子应用：写配置 + 装场景包 + 建预设集合；幂等、失败回滚
- WPF 首次启动向导：一句话输入 → 清单确认 → 完成态
- 安全边界：白名单动作；不自动下载模型、不注册外部 MCP server、不覆盖已有 API key
- 验收：全新环境说「我是大学老师，主要做科研，帮我配好」→ ≤3 次点击完成配置

### M1.4 配置 MCP 化（外部 harness 一句话配置 DocMind）

- `server/mcp.py` 新增工具：`doctor_run`、`scenario_list` / `scenario_install`、`config_get` / `config_set`（白名单字段）
- 验收：任意外部 MCP 客户端可完成体检 + 安装科研场景包

## 阶段 2：数据卫生与溯源（1–2 周，综述/复习质量的前置）

图谱错误在综述里就是错误的大纲与错误的知识，此阶段必须先于阶段 3/4 的深化。

### M2.1 实体规范化

- `graph_store.py` 新增：别名表（entity_aliases）、实体合并 API、关系删除 API
- 合并候选：名称嵌入相似度 > 阈值生成候选，UI 用户确认
- 验收：「BM25」与「BM25 检索」可合并，关系与 chunk 关联自动迁移

### M2.2 抽取覆盖修正

- 代表文本由「前 1800 字符」改为「摘要 + 首/中/尾采样」，缓解长文档只图谱化开头
- 验收：长文档抽取的实体覆盖后半部分内容

### M2.3 蒸馏卡片溯源（防回声室）

- `ingest_text` 支持 metadata（origin=`distill`、entity_id）；RAG 检索结果标注「来自你的蒸馏笔记」并在实体对话中降权
- 验收：实体对话引用蒸馏卡片时可见溯源标签

## 阶段 3：学习巩固闭环 Phase 1（2 周）——普通用户「随时学习」的核心

目标：产品从「等你来查」变成「主动找你」，攻击赛道最大痛点（只写不读的知识坟墓）。

### M3.1 学习者状态表

- `entity_interactions(entity_id, kind[visit/chat/quiz], correct, ts)`；实体查看/对话/测验自动记录
- 验收：查看实体、发起实体对话后状态表有记录

### M3.2 回顾队列 + 「今日回顾」入口

- API：`GET /v1/review/queue`（排序 = 陈旧度 × doc_count，过滤近期已回顾）
- 图谱页「今日回顾」入口：逐个聚焦实体，展示关联切片
- 验收：高权重实体 3 天未触碰后出现在队列顶部

### M3.3 出卡引擎（复习自测模式）

- 从实体关系（X–关系–Y）与切片生成 3–5 题（填空/关系判断/归类），作答后以图上真实边为反馈，结果回写学习者状态
- 验收：自测入口可用，作答记录影响回顾队列排序

## 阶段 4：科研楔子深化（2–3 周，视阶段 0 访谈结果二选一）

- **路线 A（文献综述工作台）**：多文献主题聚合视图、综述大纲编辑、按大纲逐节生成带引用草稿、引文格式（GB/T 7714 等）导出
- **路线 B（写作辅助深化）**：文献卡片 → 段落组装、观点对比（多文献同主题分歧/共识分析）、改写与润色 persona
- 共用底座：图谱 topic/entity 层 + 切片引用 + creator 导出
- 触发条件：阶段 0 访谈结论 + 阶段 1 科研包中蒸馏/综述功能的真实使用数据

## 度量与止损

| 指标 | 采集点 | 目标 | 止损动作 |
|---|---|---|---|
| 科研种子用户周留存 | 种子群回访 | ≥40% | 若综述、写作均无痛点共鸣 → 回退泛专业用户路线，场景包机制保留 |
| 场景包激活 → 首次成功生成文献卡片/综述草稿转化 | 后端埋点 | ≥50% | 低于则优先修引导流而非加功能 |
| 「今日回顾」月使用次数 | 埋点 | 活跃用户 ≥4 次/月 | 低于则巩固闭环止步于回顾队列，不加码 SRS |
| 回答引用蒸馏卡片占比 | RAG 统计 | <20% | 超标则进一步降权或默认排除 |
| MCP 调用次数（开发者渠道信号） | MCP 埋点 | 环比增长 | 持平则暂缓投入开发者侧功能 |

| 维度 | 改前 | 改后 |
|---|---|---|
| 首次上手 | 手动配 LLM、手动导入、功能自己摸索 | 一句话引导配置，场景包/集合/模型推荐一次到位 |
| 科研用户 | 通用 RAG + 图谱 + 蒸馏，综述自己组织 | 文献卡片模板化、图谱一键生成带引用综述草稿 |

## 工程实施四条铁律（完整性保障）

1. **纯增量**：新端点/新表/新字段只增不改；不动现有 API 的 response shape；必要缺列走既有幂等迁移模式（`sqlite_vec._migrate_documents_meta` 的 PRAGMA 检查 + ALTER 模式）。
2. **破坏性操作零静默**：实体合并、图谱重建一律用户主动触发 + dry-run 预览 + 合并前 JSON 快照 + 单事务执行。
3. **行为变化走开关**：抽取采样策略变更等行为类改动加 config flag，默认关、灰度开。
4. **LLM 失败降级沿用既有 skipped 模式**：onboarding 无 LLM → 表单回退；综述生成失败 → 降级为大纲；出卡失败 → 提示不阻塞。
