# DocMind 嵌入模型选型方案（魔搭社区调研，2026-09）

> 目标：为不同硬件（带不带 GPU、内存大小）给出可落地的嵌入模型方案。
> 所有模型信息已通过魔搭社区公开 API 核实（许可证、体积、ONNX 可用性、下载量），
> 评测分数为社区通行口径（C-MTEB/MTEB），标注"预估"的为经验值，实测为准。

---

## 0. 三个前提（决定方案的边界，先读）

1. **现状运行时是 fastembed（ONNX Runtime）**：它只认自己内置清单里的模型，
   塞任意 PyTorch 模型会加载失败。项目已有 `embed_model_path` 本地 ONNX 目录
   机制（`doc2mind model add-local`），但 fastembed 的 `specific_model_path`
   仍要求 `model_name` 在内置清单内——所以要让魔搭生态全面可用，需要一个
   **通用本地 ONNX 加载器**（新增 Embedder 实现，onnxruntime + tokenizers
   直接跑，按模型做 mean-pooling / last-token 池化）。这是解锁下面大多数方案的钥匙。
2. **换模型 = 维度变化 = 必须 reindex**（`doc2mind reindex` 已支持跨维度重建；
   已在 jina 768 维库上验证过，115 分块 70s）。
3. **国内网络**：HF 首页不稳，项目已默认走 hf-mirror；魔搭 API/CLI 在国内下载
   更稳，bge-m3 与 jina 官方就在魔搭放了 ONNX 成品。

## 2. 五档硬件方案

### 方案 A：无独显 + ≤8GB 内存（含老办公机）——零改动
- **模型**：保持 `bge-small-zh-v1.5`（512 维）或已切好的 `jina-embeddings-v2-base-zh`（768 维）。
- 速度预估（纯 CPU）：bge-small ~200 texts/s；jina ~60-100 texts/s。
- **结论：现状即最优档，不建议再上大模型**（换大模型会挤占内存并显著变慢）。

### 方案 B：无独显 + 16GB 内存 —— 中档质量
- **模型**：`BAAI/bge-base-zh-v1.5`（768 维，~0.4GB）或 `damo/nlp_gte_sentence-embedding_chinese-base`（768 维）。
- 速度预估：~80 texts/s；质量比 jina 小幅再升（+1~2 分，中文生态更稳）。
- 接入：需 ONNX 导出一次（`optimum-cli export onnx --model BAAI/bge-base-zh-v1.5 --task sentence-similarity`），产物登记进 `doc2mind model add-local`；或等魔搭补官方 ONNX。

### 方案 C：无独显 + 32GB 内存 / 强 CPU —— 多语言旗舰
- **模型**：`BAAI/bge-m3`（1024 维，魔搭官方 ONNX ~2.2GB）。
- 速度预估：CPU ~10-15 texts/s（大模型，批量 128 + 多线程下可接受；首次入口查询慢）。
- 亮点：100+ 语言、8192 上下文、支持稀疏向量（未来可接 D2 稀疏检索）。
- 接入：**魔搭直接下载 ONNX** → `model add-local`；reindex（512→768→1024）。

### 方案 D：NVIDIA GPU 6-8GB 显存 —— SOTA 小参数
- **模型**：`Qwen/Qwen3-Embedding-0.6B`（FP16 ~0.7GB 显存）或 `bge-m3`（GPU 推理 ~400 texts/s）。
- Qwen3-0.6B 是当前小参数里检索质量天花板（MTEB-Multilingual ~70.7）。
- 接入：ONNX 导出 + FP16（`optimum-cli export onnx --model Qwen/Qwen3-Embedding-0.6B --task sentence-similarity --fp16`）→ `model add-local`；**注意 Qwen3 查询需指令模板前缀、池化为 last-token**（通用加载器需按模型实现）。

### 方案 E：GPU ≥12GB —— 最强
- **模型**：`Qwen/Qwen3-Embedding-4B`（FP16 ~4-5GB 显存）。
- 接入同 D，但多语言/长上下文场景提升更明显；个人知识库场景收益边际递减。

### 备选：不想占本地资源
- DashScope `text-embedding-v4`（云端 API，走项目现有 ApiEmbedder；与本项目"100% 本地化"定位冲突，仅列出）。

## 3. 接入路径三种

| 路径 | 覆盖模型 | 代码量 | 说明 |
|---|---|---|---|
| 1. fastembed 内置清单 | jina-v2-base-zh / bge-small-zh 等 8 个 | 0 | **现状即可用**（设置页切 + reindex） |
| 2. 通用本地 ONNX 加载器（推荐） | 上表全部（B/C/D/E） | 新增 1 个 Embedder 实现 + 魔搭下载助手 | 解锁魔搭生态；`model add-local` 已就绪 |
| 3. 远程 API | DashScope 系列 | ~0（复用 ApiEmbedder） | 违背本地化定位，不推荐 |

---

## 4. 推荐结论

1. **当下（已执行）**：jina-v2-base-zh（768 维）在"无 GPU 中档"里已是很好的平衡点，**不用动**。
2. **下一步性价比最高**：做**路径 2 通用 ONNX 加载器**，然后按机器给用户推荐：
   - 16GB 无 GPU → `bge-base-zh-v1.5`（+1~2 分）
   - 无 GPU 但追求多语言/大上下文 → `bge-m3`（魔搭现成 ONNX，最省事）
   - 有 GPU（≥6GB）→ `Qwen3-Embedding-0.6B`（SOTA，一次性部署）
3. 每台电脑只需定一档；切换脚本 = 下载 ONNX → `model add-local` → `reindex`，我已把这条链路的坑（维度、截断、前缀/指令模板、池化）都写进了上面各档的接入注意。
